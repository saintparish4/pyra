# @pyra/docs

The Pyra documentation site, built with [Docusaurus](https://docusaurus.io/) and deployed to
GitHub Pages.

Most pages are stubs. The project is at Phase 0 and blocked on the official NERIS data
dictionary, so the site's job right now is to fix the structure — Deploy, Admin, Import,
Schema, ADRs — and give each phase somewhere to write into.

## Local development

From the repo root:

```bash
pnpm install
pnpm --filter @pyra/docs start
```

Serves on `http://localhost:3000` with hot reload.

## Build

```bash
pnpm --filter @pyra/docs build
```

`onBrokenLinks` is set to `throw`, so a dead internal link fails the build rather than
shipping. Note that CI runs lint, typecheck, and test — **not** build — so run this locally
before pushing doc changes.

## Layout

| Path | Contents |
| --- | --- |
| `docs/` | The doc pages. Sidebar order comes from `sidebar_position` frontmatter |
| `src/pages/index.tsx` | Homepage hero |
| `src/components/homepage_features/` | The section cards below the hero |
| `src/css/custom.css` | Infima theme variables |
| `docusaurus.config.ts` | Site config, navbar, footer, announcement bar |

## Adding a page

Drop an `.mdx` file in `docs/` with frontmatter:

```yaml
---
sidebar_position: 7
title: Your page
sidebar_label: Short label
description: One line, used for search and social cards.
---
```

The sidebar is autogenerated, so that is the only file you touch. Set the title in frontmatter
and don't repeat it as an `# h1` in the body — Docusaurus renders the heading for you.

## Conventions

- Say what is not written yet. Every stub ends with a "Not written yet" section listing the
  gaps, so a reader can tell missing content from complete content.
- Don't duplicate the repo. Where something is canonical elsewhere — `deploy/README.md`,
  `adr/` — link to it rather than copying, and say which one is authoritative.
- No invented NERIS fields. The dictionary is upstream at `ulfsri/neris-framework` (cloned to
  a gitignored `NERIS/` locally); anything not in it, or in the shipped code, doesn't go on
  the site as fact.

## Known gaps

- `static/img/logo.svg` and `favicon.svg` are placeholder icons, not Pyra artwork.
- The theme still uses Docusaurus's default green. The web app's palette lives in
  `apps/web/src/index.css` if the two should match.
- The blog is disabled (`blog: false`). Re-enable it along with the navbar and footer entries
  when there are release notes to publish.
